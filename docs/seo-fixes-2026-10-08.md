## Validation and artifacts

- `node scripts/test-seo-fixes.mjs` checks actual HTTP HTML, schema/answer parity, product fields, redirects, footer copies, titles, canonicals, counts, filters, and pagination boundaries. Results are under `output/seo-fixes/`.
- The first HTTP validation pass completed 417 checks, including both requested blog posts. An expanded final rerun could not finish because local development builds stalled and timed out, including with a fresh cache. Do not interpret the final acceptance-results file as a full successful run. Temporary cache/configuration changes were reverted and the test servers were stopped.
- A final server-rendering check using the actual shared component and current FAQ data rendered all 171 FAQ panels in their closed state and included “Genuine sheepskin is natural.” Its HTML and results are saved as `final-component-ssr.*`.
- Schema.org validator accepted the product, returns, FAQ, and category graphs with **zero errors and zero warnings**. Full responses are in `output/seo-fixes/schema-validator-*.json`.
- Targeted ESLint passed. Project-wide TypeScript still reports existing errors; its error output is unchanged after normalizing shifted line numbers.
- `node scripts/migrate-faq-seo.mjs` defaults to a dry run and prints each before/after change. `--apply` saves a full backup first and rejects concurrent record changes. The applied run changed 118 FAQ records; a second dry run proposed zero changes.
- Backups, full change logs, baseline HTML, and rendered acceptance HTML are in `output/seo-fixes/`. No environment credentials are included in these reports.
